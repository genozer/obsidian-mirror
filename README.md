# Obsidian Mirror (lab)

ภาพและเสียงจาก iPhone บน Windows ผ่าน AirPlay (Wi‑Fi หรือสาย USB) พร้อมลิงก์ **Browser Source สำหรับ OBS**
ไม่ต้องลงแอปบน iPhone · ใช้ “การสะท้อนหน้าจอ” ในศูนย์ควบคุม

> **สถานะ:** รอบที่ 1 ใน lab ยังไม่ได้แจกจ่าย ยังไม่ได้ผูกกับ obs-hub และยังไม่ได้ลองกับ iPhone จริง

## ยังไม่ได้ทำ

- ยังไม่ได้ลองใน OBS จริง · Android ยังไม่ได้ลองกับเครื่องจริง (เบต้า)
- ยังไม่มีลายเซ็นดิจิทัล (code signing) ช่วงเบต้า · ยังไม่ผูก login obs-hub
- กรอบโทรศัพท์ยังวาดบน CPU (หน้าต่างโปร่งใส) — ถ้าต้องการเบาสุดให้ใช้หน้าต่างธรรมดาหรือปิดภาพตัวอย่าง

## Android (สาย USB หรือ Wi‑Fi) — เพิ่ม 2026-11-19 · ยังไม่ได้ลองกับมือถือจริง

คลิกขวา → **โทรศัพท์** → **Android (สาย USB หรือ Wi‑Fi)** · ใช้ [scrcpy](https://github.com/Genymobile/scrcpy) v5.0.1 ของ Genymobile (Apache-2.0)

- เตรียมครั้งแรก: `powershell -ExecutionPolicy Bypass -File setup\get_scrcpy.ps1` (โหลด adb + scrcpy-server จาก release ทางการ ตรวจ SHA-256 → `vendor\scrcpy`, ไม่อยู่ใน git)
- มือถือ: เปิดตัวเลือกสำหรับนักพัฒนา → เปิด USB debugging → เสียบสาย → แตะ “อนุญาต”
- โปรแกรม push server ไปที่มือถือ, `adb forward`, เริ่ม `com.genymobile.scrcpy.Server 5.0.1 … raw_stream=true` แล้วส่ง H.264 เข้าพอร์ตวิดีโอเดียวกับ iPhone → ภาพตัวอย่าง ลิงก์ OBS การเข้ารหัสใหม่ ใช้ร่วมกันทั้งหมด (`app/android_source.py`, `app/sources.py`)
- ทดสอบโดยไม่มีมือถือ: `setup/fake_adb.py` ทำตัวเป็น adb + scrcpy-server (ตรวจคำสั่งตามแบบ v5.0.1 แล้วส่ง H.264) · `tests/test_android.py`
- **Wi‑Fi (Android 11+):** คลิกขวา → โทรศัพท์ → **เชื่อมต่อ Android ผ่าน Wi‑Fi (QR Code)…** → มือถือ: ตัวเลือกสำหรับนักพัฒนา → การแก้ไขข้อบกพร่องผ่าน Wi‑Fi → จับคู่อุปกรณ์ด้วยคิวอาร์โค้ด → สแกน · QR = `WIFI:T:ADB;S:<ชื่อ>;P:<รหัส>;;` (แบบเดียวกับ Android Studio) → `adb mdns services` หา `_adb-tls-pairing._tcp` → `adb pair` → `adb connect` (`app/android_wifi.py`, `app/wifi_dialog.py`) · ครั้งต่อไปโปรแกรมหา `_adb-tls-connect._tcp` ทุก 5 วินาทีตอนรอ แล้วต่อเอง
- ตรวจ QR: แคปหน้าต่างจริงแล้วถอดด้วย OpenCV ได้ข้อความตรง · adb ปลอมจำลองการสแกน/จับคู่/รหัสผิด/ต่อกลับวันถัดไป
- Windows อาจถามสิทธิ์ Firewall ให้ adb.exe ครั้งแรกที่ค้นหาในเครือข่าย (mDNS) ให้อนุญาตเครือข่ายส่วนตัว
- ยังไม่มี: เสียงจาก Android, บังคับมือถือด้วยเมาส์

## อัปเดตในโปรแกรม — เพิ่ม 2026-11-19

ลูกค้าไม่ต้องถอนแล้วลงใหม่: โปรแกรมตรวจเวอร์ชันใหม่ตอนเปิด (หลัง 20 วินาที) และทุก 6 ชั่วโมง → หน้าต่าง “มีเวอร์ชันใหม่” (อัปเดตเลย / ไว้ทีหลัง / ข้ามเวอร์ชันนี้) → ดาวน์โหลด → ตรวจไฟล์ → รันตัวติดตั้งแบบเงียบ → โปรแกรมปิดแล้วเปิดใหม่เอง · ค่าตั้งเดิมอยู่ครบ
คลิกขวา → **อัปเดตโปรแกรม** → ตรวจตอนนี้ / ตรวจอัตโนมัติ (ปิดได้) · มีเวอร์ชันใหม่ = เมนูบนสุด “⬆ อัปเดตเป็นเวอร์ชัน …”

- **ไม่เด้งกลางไลฟ์:** ถ้ามือถือส่งภาพอยู่ จะขึ้นแค่ในเมนู แล้วรอให้มือถือหลุดนาน 2 นาทีก่อนค่อยถาม · กดอัปเดตเองระหว่างส่งภาพ = ถามยืนยันก่อน
- **ปลอดภัย:** `latest.json` ต้องมีลายเซ็น Ed25519 จากกุญแจของเรา (`TRUSTED_KEYS` ใน `app/updater.py`) และบอก SHA-256 + ขนาดตัวติดตั้ง · ไฟล์ไม่ตรง = ลบทิ้ง ไม่รัน · รับเฉพาะเวอร์ชันที่ใหม่กว่า · ต้องเป็น https · ส่งไปแค่เลขเวอร์ชันใน User-Agent
- `min_version` = บังคับอัปเดต (ไม่มีปุ่มข้าม แต่ก็ยังไม่เด้งกลางไลฟ์)
- ที่อยู่: `https://obs-hub.web.app/mirror/latest.json` (`DEFAULT_URL` · ยังไม่ได้ขึ้นไฟล์ ตอนนี้ตรวจแล้วเงียบ) · เปลี่ยนได้ด้วย `update_url` ใน config.json
- รันจากซอร์ส: ปุ่มอัปเดตกดไม่ได้ (บอกให้ git pull) · `OBSIDIAN_MIRROR_DEV_INSTALL=1` ให้ลองติดตั้งจากซอร์สได้ (ไว้ลองบนเครื่อง dev)
- ตัวติดตั้ง: `installer/iPhoneMirror.iss` เพิ่ม `[Run] … Check: WizardSilent` ให้เปิดโปรแกรมใหม่หลังติดตั้งเงียบ

**ออกเวอร์ชันใหม่:**
1. แก้ `__version__` ใน `app/__init__.py` (เช่น `1.4.0-obs.2`) → `setup/build_exe.ps1` → `setup/build_installer.ps1`
2. `python setup/release_update.py sign dist/<ตัวติดตั้ง>.exe --url https://…/<ตัวติดตั้ง>.exe --th "…" --en "…" --out dist/latest.json`
3. อัปโหลดตัวติดตั้งก่อน แล้วค่อยอัปโหลด `latest.json`

🔑 กุญแจลับอยู่ที่ `%USERPROFILE%/.obsidian_mirror/update_signing_key.pem` (ไม่อยู่ใน git) — **ต้องสำรองไว้** ถ้าหาย เครื่องที่ลงไปแล้วจะไม่รับอัปเดตอีก (ต้องให้ลงใหม่เอง)

ลองแล้ว: `tests/test_updater.py` 19 ข้อ (ลายเซ็นผิด · กุญแจคนอื่น · ไฟล์ถูกสลับ/ขาด/เกิน · http · ไม่เด้งกลางไลฟ์ · ข้ามเวอร์ชัน · บังคับอัปเดต) · ในโปรแกรมจริงกับเซิร์ฟเวอร์ในเครื่อง + ตัวติดตั้งจำลอง: ขึ้นหน้าต่าง → กดอัปเดต → ดาวน์โหลด → รันด้วย `/SILENT /SUPPRESSMSGBOXES /NORESTART /CLOSEAPPLICATIONS` → โปรแกรมปิด → เปิดใหม่ใน 5 วินาที · ยังไม่ได้ลองกับตัวติดตั้ง Inno จริง (เครื่องนี้ยังไม่มี Inno Setup และตัวติดตั้งยังใช้ชื่อเดิม รอรอบ 2)

## กล้องเสมือน (ต้นแบบ) — เพิ่ม 2026-11-20

ภาพมือถือเป็นเว็บแคมชื่อ **Obsidian Mirror Camera** ให้ TikTok LIVE Studio, Discord, Zoom, Meet, Chrome ใช้ได้ · คลิกขวา → **กล้องเสมือน** → ปิด (ค่าเริ่ม) / 1280×720 แนวนอน / 1920×1080 แนวนอน / 1080×1920 แนวตั้ง · มี “วิธีใช้กล้องเสมือน…”

- ตัวกล้อง = DirectShow filter จาก [softcam](https://github.com/tshino/softcam) v1.8.1 (MIT) ที่ `native/softcam` · เปลี่ยนชื่อ, CLSID ของเราเอง `{CCBD2AC3-77A1-4925-B6DF-78E0C090295F}`, ชื่อ shared memory ของเรา, เพิ่ม `scIdleSeconds` (ดู `native/softcam/CHANGES_OBSIDIAN.md`)
- build: `powershell -ExecutionPolicy Bypass -File native\build_camera.ps1` (VS Build Tools C++) → `vendor\camera\obsidian_camera64.dll` + `obsidian_camera32.dll` (ไม่อยู่ใน git)
- ลงทะเบียนกับ Windows (ครั้งเดียว, ขอสิทธิ์ admin): `native\register_camera.ps1` · ถอด: `-Remove` · รอบ 2 ให้ตัวติดตั้งทำแทน
- โปรแกรม: `app/virtual_camera.py` · แปลงภาพใน video thread ทันทีหลังถอด (แปลงจาก thread อื่นช้ากว่า 4–6 เท่าเพราะแย่งการ์ดจอ) · บัฟเฟอร์ 3 ชุด · thread ส่งแค่ส่งต่อ · กล้อง 30 fps คงที่ · ไม่มีภาพ = จอเทาเข้ม “รอภาพจากมือถือ…” (ไม่โชว์ขั้นตอนตั้งค่า เพราะผู้ชมอาจเห็น) · **ไม่มีแอปเปิดกล้อง = ไม่แปลงภาพ**
- ภาพแนวตั้งในกล้องแนวนอน = ใส่กลาง แถบเทาเข้มสองข้าง

**วัดในโปรแกรมจริง** (ภาพจำลอง 886×1920 60 fps · ปิดภาพตัวอย่าง · RTX 3060 · % ของ 1 คอร์ จาก 12 เธรด):

| แบบ | CPU โปรแกรม | RAM |
|---|---|---|
| ปิดกล้อง | 2 % | 213 MB |

### กล้องมือถือภาพล้วน (ไม่มีปุ่ม) — เพิ่ม 2026-11-20

ปัญหาที่เจอตอนลองจริง: สะท้อนจอ iPhone ขณะเปิดแอปกล้อง = ปุ่มชัตเตอร์/แถบ PHOTO/VIDEO ติดมาในกล้องเสมือน (AirPlay คัดลอกทั้งจอ ตัดขอบก็ไม่หาย)
ทางแก้: คลิกขวา → **กล้องเสมือน** → **ภาพจาก: กล้องมือถือล้วน ไม่มีปุ่ม (สแกน QR)** → ขึ้น QR → มือถือสแกน เปิดหน้า `phone_cam.html` ของ obs-hub (ไม่ต้องลงแอป) → แตะ “▶ เปิดกล้อง”

- โปรแกรมเข้าห้องเป็น *viewer* แบบเดียวกับ `webcam_overlay.html` (`webcam_join` / `webcam_signal` เดิมของ server.js · **ไม่ต้องแก้ server หรือหน้าเว็บ**) → มือถือส่ง offer → โปรแกรมตอบ (aiortc) → ภาพวิ่งตรงในวง Wi‑Fi → `VirtualCamera.push`
- ห้อง = `om_` + สุ่ม 16 ตัว เก็บใน `camera_room` (ไม่มีข้อมูลบัญชี) · QR ส่งขนาดตามโหมดกล้อง สูงสุด 720 เส้น (แนวตั้ง = 720×1280 · 1080 เส้นทำ iPhone ร้อน) หน้าเว็บครอปให้เต็มเฟรม ไม่มีแถบดำ
- ไม่ใช้ STUN ฝั่งคอม: เครื่องนี้ STUN ทำให้คำตอบช้า 5 วิ และคอมกับมือถืออยู่วง Wi‑Fi เดียวกัน
- ข้อความ ICE จัดคิวทีละข้อ (handler ของ socketio วิ่งพร้อมกัน ICE แซง offer ได้) · ขอให้มือถือโทรซ้ำเฉพาะตอนไม่มีสายและไม่มี offer มา 8 วิ (เดิมโทรซ้อนจนสายที่กำลังต่อหลุด)
- โค้ด: `app/phone_camera.py`, `app/phone_cam_dialog.py` · ตัวจำลอง: `setup/fake_phone_cam.py` (relay แบบ server.js + มือถือปลอม)

**โหมดเบาบนมือถือ (2026-11-20 · ฟีดแบ็กจาก iPhone จริง: ไม่คม · มืดกว่า · หน่วง 200–500ms · ร้อนใน 5 นาที)**
- ไม่คม = aiortc ประเมินแบนด์วิดท์ต่ำเกิน (REMB) จนมือถือส่งแค่ ~0.4 Mbps → `use_bitrate_floor()` ไม่ขอต่ำกว่า `BITRATE_KBPS` (วงเดียวกัน · ตอนนี้ 4 Mbps) · วัดตอนตั้ง 6 Mbps: ไต่ถึง ~5.4 Mbps ใน 25 วิ
- `lite=1` (QR ของโปรแกรมส่งให้เอง · หน้า QR ของ dashboard/OBS ไม่ส่ง = เหมือนเดิมทุกอย่าง) ผ่าน 4 รอบบน iPhone จริง (v0.59.66–69):
  - ส่ง track กล้องตรงไม่ได้: iPhone ส่งภาพแนวนอน 1920×1080 แนวตั้งเหลือแถบกลาง ซูม+เบลอ → ยังผ่าน canvas แต่วาดเฉพาะตอนกล้องมีเฟรมใหม่ (30 แทน 60+/วิ)
  - ไม่มีภาพตัวอย่างเลย (แม้มุมจอก็ร้อน) · กันจอดับ: NoSleep/wakeLock อย่างเดียว iPhone ไม่ยอม ต้องมีวิดีโอเล่นบนจอ → วิดีโอจุดแดงกะพริบ 32×32 @4fps (`#keepAwake`)
  - ร้อนจริงมาจาก 1080×1920 (canvas + เข้ารหัส) → โปรแกรมขอแค่ **720×1280 @30 · 4 Mbps** (`QUALITY`) กล้องเสมือนขยายเป็นขนาดของมันเอง · ลองจริง: ร้อนน้อยลง ภาพคมชัดดี
- ภาพจากมือถือไม่ตรงสัดส่วนกล้องเสมือน → `VirtualCamera.fill` ครอปให้เต็มเฟรม (ไม่มีแถบ) · ครอปก่อนย่อ (`crop_yuv420p`)
